| PD02 | PWM0_P_2 | PWM2_H | V 相上管 | ch2 |

| PD05 | PWM0_P_5 | PWM3_L | W 相下管 | ch5 |

### 3.2 模拟采样与 ADC 通道分配

| 信号 | MCU 引脚 | ADC 通道 | 来源 |
|---|---|---|---|
| IA（A 相电流） | PF27 | **ADC0_IN0** | 低边 5 mΩ |
| IB（B 相电流） | PF26 | **ADC0_IN1** | 低边 5 mΩ |
| IC（C 相电流） | PF21 | **ADC0_IN2** | 低边 5 mΩ |
| IBUS（母线电流） | PF20 | ADC0_IN3 / ADC1_IN3 | 母线 5 mΩ（当前由 ADC1 `TRG0C` 采样） |
| NTC（温度） | PF24 | ADC1_IN10 | — |
| VA / VB / VC | PF16 / PF18 / PF19 | ADC1_IN8 / IN11 / IN13 | 分压 16:1 |
| **VN（虚拟中性点，预留）** | **PF23** | 待按数据手册确认 | **三个 1 kΩ 从 VA/VB/VC 求和**，见 §3.6 |
| VBUS（母线电压） | PF22 | ADC1_IN14 | 分压 16:1 |

`VREF1V65` = 1.65 V 偏置（双向采样，零电流 ≈ 码值 32768）

### 3.3 MT6835 磁编码器（SPI1）

| 引脚 | MCU 复用 | 用途 |
|---|---|---|
| PC10 | SPI1_SCLK | 时钟（外加 `LOOP_BACK`） |
| PC11 | **GPIO_C_11**（不是硬件 CS） | 片选，软件手动拉 |
| PC12 | SPI1_MISO | 数据入 |
| PC13 | SPI1_MOSI | 数据出 |

CS 用普通 GPIO 而不是 SPI1_CS_0，原因：SPI 组件的非阻塞(DMA)收发不碰 CS，且链式 DMA 分支里有
`assert(context->write_cs != NULL)`，要求由软件控制片选。

### 3.4 栅极驱动

- U2：20 脚三相栅极驱动，输入 `M0_HIN1~3` / `M0_LIN1~3`，输出 `M0_HO/LO1~3`
- **无故障输出引脚**（详见 `限制.md`）

### 3.5 通信与电源

- EtherCAT：2 路 PHY + 2 个 RJ45（HR911105A）
- 电源：DCBUS(VBUS) → 12V → 5V → 3.3V，含防反接/防过压/缓启动

### 3.6 虚拟中性点采样（硬件已设计，固件未实现，留给无感）

**电路**：VA / VB / VC 各自串 1 kΩ 后接到同一个节点，由 **PF23** 采样。

```
Vn = (Va + Vb + Vc) / 3        # 三相星形的虚拟中性点 / 零序分量
```

⚠️ HPM5E31 的 ADC 输入是**固定功能脚**，IOMUX 里 PF23 只有
`GPIO_F_23 / SDM0_CLK_3 / USB0_OC`（没有 ADC 复用项），所以 PF23 对应的
`ADC1_INx` 通道号要按数据手册引脚表确认，别照抄现有通道假设。

**用途（按对项目的价值排序）**

| 用途 | 说明 |
|---|---|
| **反电势直接测量** | `e_a = Va − Vn − R·i_a − L·di_a/dt`。比 SMO 干净：无积分漂移、无相位延迟；低速只要 EMF 幅值够就能用 |
| **三次谐波反电势位置估计** | 三次谐波幅值随转子角变化，**表贴式电机也能用** —— 正好补 4310 凸极弱、HFI 用不了的短板 |
| **BEMF 过零换相** | 传统六步方波无感换相：各相反电势与虚拟中性点比较取过零点 |
| **死区/管压降补偿校验** | 死区造成共模畸变，Vn 能反映实际误差；现在的 `foc_deadtime_comp()` 按固定 100 ns 开路算 |
| **缺相/对地短路检测** | `Va+Vb+Vc` 明显偏离中性点 → 缺相或驱动不对称 |
| **相电压采样自检** | 三路分压器一致性、上电中点漂移（`FOC.Va_midpoint` 目前只在上电标一次） |

**采样注意**

- 源阻抗：三个 1 kΩ 并联 = **333 Ω**，对 ADC 采样保持偏大（`ADC_SAMPLE_CYCLE = 10`）。
  建议节点对地加 **1~10 nF**（给采样电容供电荷 + 滤开关毛刺），或把串联电阻降到 100 Ω 级。
- Vn 里含 **SVPWM 的三次谐波共模**（马鞍波），属正常；用 `Va − Vn` 差分会自动抵消，
  也可以反过来用它验证 SVPWM 和死区补偿。

**以后做无感时的实现步骤**

1. PF23 加进 ADC1 的 1 kHz 软件队列（不占 20 kHz 快通道），先打印 `Vn` 和 `Va+Vb+Vc` 看波形/噪声
2. 计算 `e_a/b/c = Vph − Vn − R·i − L·di/dt`（R/L 用标定值），用编码器当"真值"校验 EMF 幅值与相位
3. EMF 幅值/相位法或三次谐波法做低速无感，与 SMO 交叉校验
4. 验证通过后再考虑拆编码器

## 6. ADC 配置（`core/inner/src/adc.c`，已上板实测）

| 项 | 值 |
|---|---|
| 外设 / 中断 | ADC0 / `IRQn_ADC0`，PLIC 优先级 1（电流环中断） |
| 时钟 | `clock_adc0` / `clock_adc1`，源 = AHB(200 MHz)，转换时钟分频 4 → **50 MHz** |
| 模式 | 抢占（PMT / 注入），16 位，采样保持 10 个 ADC 时钟 |
| ADC0 队列 | `TRG0A`：IA / IB / IC 三通道，**只在最后一相开中断**（IBUS 不在其中） |
| ADC0 触发链 | PWM CMP20（计数=1）→ TRGO_0 → TRGM → `ADCx_PTRGI0A`(TRG0A) |
| ADC1 队列 | `TRG0B`：VA / VB / VC / VBUS 四通道，软件 1 kHz 触发，末项开中断（不接 NVIC） |
| ADC1 母线电流 | `TRG0C`：IBUS 单通道，软件 1 kHz 触发，不开中断（轮询 DMA） |
| 结果读取 | **用 DMA**：ADC 内置 AHB DMA 直接把结果写内存，中断 / 任务 / 轮询读 `*_dma_buf[]` |
| `adc_ahb_en` | `true`（打开 ADC 内置 DMA；目标地址由 `adc16_init_pmt_dma()` 设） |
| DMA 缓冲 | `adc_dma_buf[48]` / `adc1_dma_buf[48]`（抢占模式固定 192 字节），放 **`.noncacheable.bss`**，4 字节对齐 |
| DMA 数据格式 | 每通道一个 32 位字：`result:16 / adc_ch:5 / trig_ch:4 / seq_num:2 / cycle_bit:1`；队列 `q` 落在基址 + `q*0x10` |
| 帧校验 | 完成标志（或 DMA 元数据）+ `adc_ch/trig_ch/seq_num` 全部匹配才接受，否则丢弃并计数 |
| 数据出口 | 全局 `volatile foc_data_t FOC`（成员 `Ia/Ib/Ic/Ibus` 存原始码值，换算在 `foc.c`） |
| 实测结果 | ADC0 中断 40 kHz；零点 IA≈33055 / IB≈33290 / IC≈33160 |

> ⚠️ **关键硬件行为（已实测）**：`TRG_CMPT_FLAG` **只为设置了 `INTEN` 的队列置位**；
> 抢占 DMA 的 `CYCLE` 位恒为 1，不能用来判新帧（用"清 `adc_ch` 再等它变有效"）。
> 详见 `docs/superpowers/specs/2026-09-21-adc-sampling-repair-design.md`。

## 7. MT6835 配置（`core/outer/src/mt6835.c`）

| 项 | 值 |
|---|---|
| 芯片 | MT6835，AMR 磁编码器，21 位绝对角度，SPI 最高 **16 MHz** |
| SPI | SPI1，主机，**8 位帧**，MSB first，CPOL=1 + CPHA=1（**Mode 3**） |
| SCLK | 10 MHz（`MT6835_SPI_SCLK_FREQ`） |
| 片选 | PC11 普通 GPIO，软件按帧拉低/拉高 |
| 收发方式 | `hpm_spi_transmit_receive_nonblocking()` + DMA，一帧 6 字节 |
| 命令帧 | 发送 `A0 03 00 00 00 00`；角度在收到的第 3/4/5 字节 |
| 角度解析 | `(rx[2]<<16) \| (rx[3]<<8) \| (rx[4] & 0xF8)`，低 3 位丢掉（21 位有效） |
| 单圈分辨率 | `MT6835_CPR = 2^24`（角度统一按 24 位处理，芯片 21 位左移 3 位） |
| 方向修正 | `MT6835_DIR`（`+1` / `-1`，标定出方向后改；`-1` 时单圈值取镜像） |
| 累计计数 | `shadow_count`：单圈值差分做过零修正后累加，可正可负，标定数圈用 |
| 速度估计 | **二阶 PLL**（`pll_kp` / `pll_ki` / `pll_pos` / `pll_vel`），不再用两次角度差分 |
| PLL 增益 | 带宽 `MT6835_PLL_BW_HZ = 100 Hz`，`kp = 2·ω`，`ki = 0.25·kp²·T`，**T 取决于调用频率** |
| 静止死区 | `MT6835_PLL_SNAP_VEL`（约 1 转/分），速度低于它就归零，防静止漂移 |
| 调用频率 | `MT6835_UPDATE_FREQ = 5000`（enc_task），**改频率必须重算 PLL 增益** |
| 零位偏移 | `MT6835_ANGLE_OFFSET`（当前 16663688，**换磁铁安装必须重标**） |
| 极对数 | `MT6835_POLE_PAIRS`（当前 7，按实际电机改） |
| 对外接口 | `mt6835_init()` / `mt6835_start_read()` / `mt6835_update_angle()` / `mt6835_reset()`，数据在 `volatile mt6835_data_t MT6835` |
| 编译依赖 | 必须在编译宏里开 **`USE_DMA_MGR=1`**，并在 `main()` 里先调 `dma_mgr_init()` |

## 11. 中断通路（FreeRTOS + 非向量模式）

> 这一节是排查 MT6835「DMA 传完了但回调不进」时挖出来的，是理解本工程所有中断的前置知识。

**一句话结论：外设中断能不能进，取决于 `mstatus.MIE`；而打开 `mstatus.MIE` 的只有 `vTaskStartScheduler()`。**

**✅ 已上板验证。** 加上 `vTaskStartScheduler()` 之后的实测日志：

```
[IRQ] before scheduler: mstatus=0x80006000 MIE=0     ← 调度器之前，中断确实是关的
[IRQ] in task:          mstatus=0x80006088 MIE=1     ← 调度器之后打开了
[DBG] err=0 rx=1 tx=1 frame=1 stuck=0 | busy=0 ready=1   ← DMA 回调正常触发
[DBG] irq40 MIE=1 PLICen=1 PLICpend=0 PLICprio=1 thr=0  ← PLIC 侧也全对
[DBG] dma INTTCSTS=0x00000000                            ← 已被 ISR 消费并清零
```

原因链（4 步）：

1. `CONFIG_FREERTOS=1` → `startup.s` 把 `mtvec` 指向 FreeRTOS 的 `freertos_risc_v_trap_handler`，**不再**是 SDK 的 `irq_handler_trap`。
2. `USE_NONVECTOR_MODE=1` → `startup.s` 清掉 `MMISC_CTL` 的向量中断位，改成「claim 中断号 + 查表分发」。
3. `CONFIG_DISABLE_GLOBAL_IRQ_ON_STARTUP=1` → `soc/HPM5E00/HPM5E31/system.c` 的 `system_init()` **跳过** `enable_global_irq(CSR_MSTATUS_MIE_MASK)`。
4. 于是从复位到 `vTaskStartScheduler()` 之间，CPU 全局中断一直是关的。这段时间里 **DMA 传输照样能完成（纯硬件，不需要 CPU），但传输完成中断进不来，回调永远不执行** —— 现象就是「缓冲里数据是对的，回调计数器是 0，`spi_busy` 永远不清、`stuck` 一直涨」。

`xPortStartScheduler()`（`middleware/FreeRTOS/Source/portable/GCC/RISC-V/port.c`）负责把中断补上：

| 步骤 | 作用 |
|---|---|
| `vPortSetupTimerInterrupt()` | `mtimecmp = mtime + 24000`，配好 MCHTMR 的 1 kHz tick |
| `csrs mie, 0x880` | 打开 `MTIE`（bit7，定时器中断）和 `MEIE`（bit11，外部中断） |
| `xPortStartFirstTask()` | 置 `mstatus.MIE`，然后 `mret` 进第一个任务 |

**完整分发链（本次实测确认）：**

```
PLIC 拉高 IRQn_HDMA
  → mtvec = freertos_risc_v_trap_handler        startup.s（CONFIG_FREERTOS=1 时）
  → freertos_handle_interrupt                   port.c:328
        __plic_claim_irq() 拿到中断号
        __vector_table[中断号]()                 表项由 SDK_DECLARE_EXT_ISR_M 生成
  → default_isr_<IRQn_HDMA> → dma0_isr          hpm_dma_mgr.c:115
  → dma_mgr_isr_handler(HPM_HDMA, 0)
        要求通道 is_allocated，且 (CTRL & INTTCMASK) == 0，且 INTTCSTS 对应位置位
  → chn_ctx->tc_cb → dma_channel_tc_callback    spi.c:1162 里注册
  → mt6835_rxdma_callback / mt6835_txdma_callback
```

**三个容易踩的坑：**

- **不要在 `vTaskStartScheduler()` 之前手动调 `enable_global_irq()`「试试看」**。那时 `mtvec` 已经是 FreeRTOS 的 trap handler，而 FreeRTOS 的 `pxCurrentTCB`、ISR 栈还没建立，一开中断就可能跑飞。
- `CTRL` 里的 `INTTCMASK` / `INTABTMASK` / `INTERRMASK` / `INTHALFCNTMASK` 是 **MASK 语义：0 = 中断开，1 = 中断关**（和直觉相反）。所以 `CTRL = 0x0002801C` 表示 bit1(TC)=0，**TC 中断是开着的**，别误判。
- `hpm_dma_mgr.c` / `spi.c` 是从 SDK 组件目录拷来的，`dma0_isr` 由 `SDK_DECLARE_EXT_ISR_M(IRQn_HDMA, dma0_isr)` 生成。换芯片型号时 `IRQn_HDMA` 会变，宏会自动跟着变，不用手改。

### 11.1 中断链路自查表（需要时临时加打印）

出问题时按这张表加几行 `printf`，一次就能看清中断卡在哪一层。
（本次排查用的探针代码已经删掉了，这里留档备用。）

| 打印项 | 含义 |
|---|---|
| `MIE` | `0` = CPU 全局中断没开（没调 `vTaskStartScheduler()`，或烧的是旧固件） |
| `PLICen` | `0` = PLIC 没使能 `IRQn_HDMA`（在 HPM5E31 上 = 40） |
| `PLICpend` | `1` = 中断挂起了但没被响应；这时对比 `thr` 和 `PLICprio` |
| `INTTCSTS` | 对应通道位置位 = DMA 报过传输完成，但没人消费 |

对应寄存器：`read_csr(CSR_MSTATUS)`、`HPM_PLIC->TARGETINT[0].INTEN[IRQn_HDMA/32]`、
`HPM_PLIC->PENDING[IRQn_HDMA/32]`、`HPM_PLIC->PRIORITY[IRQn_HDMA]`、
`HPM_PLIC->TARGETCONFIG[0].THRESHOLD`、`HPM_HDMA->INTTCSTS`。

> **注意**：只能**读** `INTTCSTS`，绝不能调 SDK 的 `dma_check_transfer_status()` —— 那个函数是 W1C 语义，读的同时会把标志清掉，等于把证据抹掉。

### 11.2 排查时先确认「烧进去的是不是新固件」

SES 的产物在 `hpm5e00evk_flash_xip_debug\segger_embedded_studio\Output\Debug\Exe\foc.elf`（含 `.bin` / `.asm` / `.map`）。
`hpm5e00evk_flash_xip_debug\output\` 下另有一份 **CMake 构建的旧产物**，别拿它去烧。

怀疑「改了没生效」时，按时间戳串一遍就能确认编译链是否走到：

```
core/inner/src/main.c            源文件改动时间
core/.../Output/Debug/Obj/.../main.c.o    目标文件应比源文件新
core/.../Output/Debug/Exe/foc.elf        应比目标文件更新
```

`foc.map` 里搜 `mt6835_task`、`foc.asm` 里搜 `main start`，能直接确认符号和字符串有没有进镜像。

## 12. 调试串口（`printf` 输出）

| 项 | 值 |
|---|---|
| 外设 | **UART0** |
| TX / RX | **PA00 / PA01**（`IOC_PA00_FUNC_CTL_UART0_TXD` / `IOC_PA01_FUNC_CTL_UART0_RXD`） |
| 波特率 | 115200，8 数据位，无校验，1 停止位 |
| 板级参数位置 | `core/inner/inc/sys.h` 里的 `SYS_CONSOLE_*` 宏，换板子只改这一处 |
| 初始化 | `sys.c` 的 `sys_console_init()`，由 `sys_board_init()` 调用 |
| 换行 | `\n` 会自动补成 `\r\n`（在 `hpm_debug_console.c` 里做的），串口助手不用特殊设置 |

### 12.1 输出是怎么接上的

```
printf()                        ← 应用代码
  → SES 的 RTL 库 printf        (prinops.o, 来自 libc_rv32imafc_f_balanced.a)
  → __SEGGER_RTL_X_file_write() ← hpm_debug_console.c 里定义，串口重定向的钩子
  → uart_send_byte()            ← 真正往 UART0 写
```

### 12.2 三个必须同时满足的前提

少任何一个，日志都不会从串口出来（而且**不会报错，只是没输出**）：

1. **编译宏里不能有 `CONFIG_NDEBUG_CONSOLE=1`**
   否则 `hpm_debug_console.c` 整个编译成空壳：`console_init()` 返回失败、`__SEGGER_RTL_X_file_write()` 是空函数。
   > 判据：map 里 `__SEGGER_RTL_X_file_write` 只有十几字节 = 空壳；上百字节 = 真版本。
2. **`SEGGER_RTT_Syscalls_SES.c` 必须排除编译**
   它自己定义了 `printf()`，会把 SES 库里的 `printf` 顶掉，日志就又跑到 RTT 去了。
   SES 排除文件的属性名是 **`build_exclude_from_build="Yes"`**（注意有 `build_` 前缀），加在 `<file>` 的 `<configuration>` 上。
3. **先配引脚，再开时钟**
   `sys_console_init()` 里引脚复用写在 `clock_add_to_group()` **之前**。反过来的话，配引脚那一刻 RX 上的电平跳变会被当成起始位收进去。

### 12.3 日志一点都没有时的排查顺序

1. 硬件：PA00 接 USB-TTL 的 **RX**，**GND 必须共地**（模块的 TX 不用接）
2. 串口助手：115200-8-N-1，选对 COM 口
3. 编译宏：`CONFIG_NDEBUG_CONSOLE` 有没有残留
4. `foc.map`：搜 `__SEGGER_RTL_X_file_write` 看是真版本还是空壳；搜 `printf` 看它来自 `libc_*.a` 还是 `SEGGER_RTT_Syscalls_SES.c.o`
