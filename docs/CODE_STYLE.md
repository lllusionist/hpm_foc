# 代码规范

依据 [Linux 内核编码风格](https://www.kernel.org/doc/html/v4.15/translations/zh_CN/coding-style.html)，
并结合本 FOC 项目的实际约定。

**每次修改代码前对照本文自查一遍，并在回复中报告检查结果。**

---

## 1. 缩进

- **用 Tab，8 个字符宽度**，不混用空格。
- 续行用 Tab 对齐到合适位置，不要用空格凑。

## 2. 行长

- **每行不超过 80 列。**
- 超了要拆行，不要硬压（把 `if` 条件拆成多行，或提取临时变量）。

```c
/* 好 */
if ((mCalibStep == CS_MOTOR_J_DEC) && (j_cnt > 30U) &&
    (encoder.vel < 0.3f)) {
```

## 3. 大括号

| 场景 | 写法 |
|---|---|
| **函数** | `{` **单独一行** |
| **控制语句** | `{` **与语句同行** |
| **单条语句** | **不加 `{}`** |

```c
/* 好：函数 */
static void foc_openloop_step(void)
{
	...
}

/* 好：控制语句 */
if (ol_stage == 0) {
	ol_angle = 0.0f;
}

/* 好：单条语句不加 {} */
if (ol_angle >= M_2PI)
	ol_angle -= M_2PI;

/* 不好 */
if (ol_angle >= M_2PI) { ol_angle -= M_2PI; }
```

## 4. 空格

- **关键字后加空格**：`if (`、`for (`、`while (`、`switch (`
- **函数调用不加**：`foo(x)`、`sizeof(x)`
- **括号内不加**：`if (x)` 而非 `if ( x )`
- **二元/赋值运算符两边加**：`a = b + c`、`a <= b`、`a && b`
- **一元运算符后不加**：`!x`、`~x`、`++i`、`&x`、`*p`
- **逗号后加，前不加**：`f(a, b, c)`
- **结构体成员访问不加**：`a.b`、`a->b`

## 5. 命名

| 类别 | 规范 | 示例 |
|---|---|---|
| **宏、常量** | 全大写 + 下划线 | `OL_SELFTEST_IQ`、`PWM_DEAD_TIME_NS` |
| **函数** | 小写 + 下划线 | `foc_deadtime_comp()` |
| **局部变量** | 小写 + 下划线，可短 | `i`、`err`、`dt` |
| **全局变量** | 小写 + 下划线，描述性强 | `ol_rps_ref` |
| **类型** | 小写 + 下划线 | `foc_data_t`、`tConfig` |

- **不用 camelCase、不用匈牙利命名。**
- 局部变量要短（`tmp`、`i`），全局变量要清楚（`encoder_offset`）。

## 6. 注释

- **新代码用 `/* */`**，不用 `//`（旧代码逐步替换）。
- **只写"为什么"，不写"是什么"** —— 代码本身能说明是什么。
- **函数头写清**：用途、前提条件、已知陷阱。
- **危险操作必须注明后果。**

```c
/* 好：解释了为什么 */
/* ITH 取宽过渡带: 窄带时补偿量近似方波, 低速会出现可听啸叫 */

/* 不好：重复代码字面意思 */
/* 把 ca 加到 dtc_a 上 */
FOC.dtc_a += dt_comp * ca;
```

## 7. 魔法数字（禁止）

即使加了注释解释，也必须用宏表达意图。

```c
/* 不好 */
if (ol_tick > (OL_ALIGN_MS * 40U))   /* 40 拍 = 1ms */

/* 好 */
#define OL_TICKS_PER_MS  (PWM_FREQ_HZ / 1000U)

if (ol_tick > (OL_ALIGN_MS * OL_TICKS_PER_MS))
```

## 8. 函数

- **短小，一个函数只做一件事。**
- **局部变量在函数开头集中声明。**
- **嵌套不超过 3 层。**
- **重复 3 次以上的逻辑抽成辅助函数**（例如 clamp）。

## 9. 本项目特定约定

### 数据归属

| 变量 | 用途 |
|---|---|
| `Config.*` | **可掉电保存的参数**（Flash + CRC 校验）|
| `FOC.*` | **运行时状态**（`volatile`，中断与任务共享）|
| `Controller.*` | **控制环状态** |

### 在中断里

- **`foc_adc_callback()` 运行于 40kHz ADC 中断**，任何操作都要考虑耗时。
- **`printf` 必须限流**（用计数器分频），否则会阻塞中断。
- **避免浮点除法**，可用乘法替代。

### 调试 / 自测代码

- **必须有宏开关，默认关闭**（如 `OL_SELFTEST_IQ = 0.0f`）。
- **注释写明"验证完置 0"**，避免遗留在正式固件里。
- **上电即动作的自测，注释里必须警告。**

### 功率级安全（血泪教训）

- **绝不能用 `FOC_voltage()` 做闭环控制或开环拖动。**
  它会**旁路电流环**，参数一旦不准（如 `λ` 低估 26%），电流就会完全失控。
  实测后果：10rps 时电流 −7A，**能量回灌母线，接近炸板**。
- **开环拖动必须走 `FOC_current()`**：只替换角度来源，电流仍由电流环锁定。
- **任何"直接给电压"的代码，写之前必须先算：**
  1. 电流会是多少？(`I = (V − E) / R`)
  2. 参数错了最坏是多少？
  3. **有什么东西限制它？如果没有，就不能这么写。**
